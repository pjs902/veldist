# veldist audit — 2026-10-14

Ponytail audit, read-only. Nothing below has been applied yet. Each item was
reproduced with a small script during the audit. Fast suite at audit time:
300 passed, 69 slow skipped, 2 xfail.

## Must fix

### V1. 2D: precise stars with correlated errors get a wrong design-matrix row
`src/veldist/veldist2d.py:255-258`, `:290-350` (`_design_matrix_gl_quadrature`)

- Stars with `cov[0,1] != 0` (most Gaia stars) go through a 2x2 Gauss-Legendre
  rule per cell. Four nodes cannot integrate a Gaussian narrower than a cell.
- Case: a star at a cell centre, cell width 1, rho = 1e-6. Error 0.3 -> row sums
  to 0.84 (should be 1). Error 0.1 -> row sums to 0.0038, so the star almost
  vanishes. With rho < 1e-12 it takes the exact path instead, so two near-identical
  stars give very different rows.
- `tests/test_veldist2d.py:196-207` only uses cells much smaller than the errors,
  so it cannot catch this.
- Fix: subdivide each cell into n x n sub-cells with
  `n = max(1, ceil(2 * cell_width / min(sx, sy)))` per star. Add a test that
  compares a star with error = 0.1 cell to the exact diagonal path.

### V2. `add_data` accepts stars the model cannot use
`src/veldist/veldist.py:639-663`, `src/veldist/veldist2d.py:801-832`

- In 2D, a star outside the grid on both axes gets an all-zero row (the
  float32 cast turns the 1e-30 floor into 0). log-likelihood = -inf, NUTS fails
  with `Unit distribution got invalid log_factor parameter`, and
  `fit_all_bins_2d` returns the bin as `None`. One such star among 60 kills the
  bin. This is a likely cause of the "Cannot find valid initial parameters"
  failures on real HST bins.
- In 1D the same star is silently ignored but still counted in `n_stars`,
  which becomes `bin_flux`.
- A NaN velocity gives an all-NaN row in both versions.
- Fix: in both `add_data`s, raise on any non-finite input. Warn and drop stars
  whose row sums to less than ~1e-3. In 2D, clip each chunk to 1e-30 before the
  float32 cast, as the 1D path already does.

## Should fix

### V3. DYNAMITE writers crash on pixel IDs above the number of solvers
`src/veldist/veldist.py:1555-1560`, `src/veldist/dynamite2d.py:67-72`

- `np.where(mask, orig_to_new[pixel_ids], 0)` evaluates the index for every
  pixel before masking. Case: `pixel_bin_ids=[1, 2]` with one solver raises
  `IndexError`, although the docstring promises such pixels become 0 (masked).
  This happens when writing a subset of bins.
- Fix: `orig_to_new[np.clip(pixel_ids, 0, n_total)]`. Do it once, in the
  shared helper from V6.

### V4. `compute_moments` gives the wrong kurtosis
`src/veldist/analysis.py:98-160`

- It adds the within-cell (Sheppard) correction to the variance but not to the
  4th moment. `compute_summary` already fixed this mismatch.
- Case: an exact Gaussian with h/sigma = 0.78. `compute_moments` -> excess
  kurtosis -0.272; `compute_summary` -> -0.005.
- Still used by the slow tests in `tests/test_inference.py` (lines 74-346).
- Fix: delete it and switch those tests to `compute_summary` (or make it a
  thin wrapper around `compute_summary`).

### V5. 1D `fit_all_bins` keeps every draw of every bin in memory
`src/veldist/veldist.py:1268-1282`

- 1D keeps all 12,000 draws of `intrinsic_pdf`, plus `d3` and the design
  matrix, per bin. About 2-4 MB per bin on the oMEGACat grid; ~4-8 GB at
  ~2,000 bins (estimate, not measured). The 2D loop already slims results
  (`veldist2d.py:1118-1140`) after it reached 36 GB.
- Fix: after `clip_uncertainties()`, keep only `intrinsic_pdf` (float32,
  optionally thinned) and set `matrix=None`, as 2D does.

### V6. The aperture/bins writer exists twice
`src/veldist/dynamite2d.py:31-85` vs `src/veldist/veldist.py:1530-1574`

- The copy exists "because importing that function would pull in astropy",
  but the 1D writer imports astropy lazily and astropy is a required
  dependency. Both copies carry the V3 bug.
- Fix: keep one `_write_aperture_and_bins_files` in `veldist.py`, call it from
  both writers. About -45 lines.

## Nice to have

### V8. Importing `veldist2d` turns on float64 process-wide
`src/veldist/veldist2d.py:34`

- `jax.config.update("jax_enable_x64", True)` at import time makes later 1D
  fits run in float64 (2x memory, slower) depending only on import order.
- Note: kinutils also enables x64 at import, so in a process that imports
  kinutils this is always on anyway.
- Fix: say so at the top of `veldist.py`, or pass float64 only where 2D needs it.

### V9. Parallel workers can interleave lines in the failure log
`src/veldist/veldist2d.py:1041-1052`

- Records include full JAX tracebacks (often > 4-8 KB). Buffered `f.write`
  then makes several syscalls, so two failing workers can interleave lines
  and corrupt the JSONL. (The cited atomic-write rule is for pipes, not files.)
- Fix: `open(path, "ab", buffering=0)` and one `f.write(line.encode())`, or
  cut the traceback to its last 2 KB.

## Withdrawn

### V7. `ObservingProfile.from_data` uses full ptp for `rotation_span`
Not a bug: `calibration.py:380-382` documents the choice ("the grid has to
hold the worst bin, and a percentile range discards exactly the tail that
defines it"), and `min_stars=10` limits single-bin noise.

## Cross-project notes (kinutils / paper_plots)

- `veldist.set_host_devices()` silently did nothing after `import kinutils`,
  because kinutils created a PRNG key at import time and so initialised the
  JAX backend with 1 device. Fixed on the kinutils side (module-level keys and
  the XLA_FLAGS line removed); nothing to change here.
- kinutils' `comp_veldisp_MLE` (could return sigma = 1e109 when errors exceed
  the spread) is being removed in favour of `veldist.baseline.gaussian_mle`.
